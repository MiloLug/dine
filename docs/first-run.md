# First run: setting up dine on a new PC

Tested on Arch Linux in WSL2 (Windows 11), iPhone 13 on iOS 27.0.1, Swift 6.4.1, xtool 1.22.2,
Xcode 27. About 45 minutes, mostly unattended (SDK extraction, ART build, symbol download).

Rule for this repo: tools come from a package manager (pacman, paru, uv). The only manual
downloads are things no package manager ships, and they go to gitignored dirs **inside the repo**
(`out/`), never to `~/.local` or other system dirs.

## Where every tool comes from

| Source | Tools |
|---|---|
| **pacman** | `base-devel` (gcc, make, binutils, pkgconf), `git`, `curl`, `clang`, `lld`, `llvm` (llvm-ar/ranlib/otool/nm, dsymutil), `cmake`, `ninja`, `socat`, `libimobiledevice`, `fuse2`, `uv`, `rustup` (cargo for accord), `jdk8-openjdk`, `jdk21-openjdk` (runs d8), `patchelf`, ATL build libraries (below); for runtime tests: `smali` |
| **AUR (paru)** | `swift-bin` (Swift 6.4 + its lldb), `ipsw-bin` (splits the phone's dyld shared cache), `wolfssl-jni`, `bsd-compat-headers`, `android-sdk-build-tools` (d8 for the ART/ATL dex build, zipalign); for runtime tests: `jasmin` |
| **uv → `.venv`** (`pyproject.toml`, `uv.lock`) | CPython 3.12, `pymobiledevice3`, `meson` |
| **Manual, in repo** | xtool AppImage → `out/tools/bin/xtool`; `Xcode_27.xip` → `out/downloads/` (deleted after use) |
| **Sibling repo** | [`wsl-quickack`](../../wsl-quickack) (`sudo make install`): keeps `quickack` on WSL's routes to Windows; [`dine-accord`](../../dine-accord) (`git clone git@github.com:MiloLug/dine-accord.git ../dine-accord`): accord, built by `ios run` (`DINE_ACCORD` overrides the path) |
| **Windows** | Apple Devices or iTunes (Apple Mobile Device Service) |

State that tools manage themselves, outside the repo (leave it there):
- `~/.swiftpm/swift-sdks/darwin.artifactbundle`: the iOS SDK, built by `xtool sdk install`
  (SwiftPM's SDK location; ~15 min to rebuild).
- `~/.local/share/uv/python/`: uv's Python store (the `.venv` interpreter lives there).
- xtool's Apple ID session, pymobiledevice3's pairing/DDI caches.
- `/etc/systemd/system/{usbmuxd-bridge,dine-tunneld}.service`, installed from `tools/systemd/`.
- `/usr/local/sbin/wsl-quickack` and `/etc/systemd/system/wsl-quickack.service`, from `../wsl-quickack`.

Generated by scripts into `out/` (gitignored). Some are slow to recreate, so don't
`rm -rf out` casually:

| Dir | What | Recreate |
|---|---|---|
| `out/tools/bin/` | xtool AppImage | re-download (step 4) |
| `out/ios-symbols/` | phone's system dylibs for lldb, 6.7 GB per iOS build | `tools/dine ios symbols`, ~6 min |
| `out/linux/` | ATL/ART build + prefix | `tools/dine linux build`, ~10 min |
| `out/lldb/` | relocated lldb (223 MB) | automatic on next `$DINE_LLDB` |
| `out/ios/` | native libs, ART and ATL archives and their libraries (`lib/`, `include/`), compiled asset catalogs (`assets/<App>`) for iOS | `tools/dine ios run`, seconds; `tools/dine ios build-art` for ART, `tools/dine ios build-atl` for ATL |
| `out/tests/runtime/` | ART run-test sources, builds, run outputs | `tools/dine test runtime`, ~5.5 min |

## 0. Windows + phone prerequisites

1. Install **Apple Devices** (Microsoft Store) or **iTunes**. Either one installs the
   *Apple Mobile Device Service* (AMDS), which owns the USB connection and listens on
   `127.0.0.1:27015`. Check that it's running: `Get-Service "Apple Mobile Device Service"`.
2. Plug in the iPhone via USB, unlock it, and tap **Trust This Computer**. The pairing record ends
   up in `C:\ProgramData\Apple\Lockdown\<UDID>.plist`, and WSL reuses it through AMDS.
3. Turn on **Developer Mode** on the phone: Settings → Privacy & Security → Developer Mode. This
   needs a reboot plus a confirm prompt after boot. The toggle only appears once a developer tool
   has used the phone. If it's missing, it shows up after the first install attempt in step 7;
   enable it then, reboot, and retry.
4. `%UserProfile%\.wslconfig` needs mirrored networking, so WSL can see Windows' `127.0.0.1`:
   ```ini
   [wsl2]
   networkingMode=Mirrored
   [experimental]
   hostAddressLoopback=true
   ```
   `/etc/wsl.conf` needs `[boot] systemd=true`. Then run `wsl --shutdown` and restart WSL.
   - Without mirrored networking, use the netsh portproxy + firewall-rule workaround from
     [xtool#19](https://github.com/xtool-org/xtool/issues/19#issuecomment-2898986718) and set
     `USBMUXD_SOCKET_ADDRESS=<windows-host-ip>:27015`.
   - **Don't** use usbipd to pass the iPhone into WSL. It breaks with "message was too large" /
     `AFCClient.Error.muxError`, and it takes the phone away from Windows.
5. In WSL: Arch with `sudo` and `paru`. Check the bridge target from WSL:
   `bash -c '</dev/tcp/127.0.0.1/27015' && echo ok`.

## 1. System packages (pacman + paru)

```sh
sudo pacman -S --needed base-devel git curl clang lld llvm cmake ninja socat libimobiledevice \
  fuse2 uv rustup jdk8-openjdk jdk21-openjdk patchelf \
  bubblewrap libbsd libunwind elfutils mesa expat icu libpng lz4 openssl xz zlib libcap valgrind \
  zip alsa-lib ffmpeg gtk4 gtk4-layer-shell graphene libgudev libportal libsecret sqlite \
  vulkan-icd-loader vulkan-headers wayland wayland-protocols webkitgtk-6.0 openxr glib2-devel \
  libglvnd libdrm \
  smali
paru -S --needed swift-bin ipsw-bin wolfssl-jni bsd-compat-headers android-sdk-build-tools jasmin
```

- The second and third lines of the pacman command are build dependencies of the ATL/ART stack.
- `android-sdk-build-tools` provides `d8`, which dexes libcore (dine-art), ATL's jars and the
  runtime tests. It needs Java 11+, so everything calls it through `tools/bin/d8` (on `PATH` via
  `env.sh`), which runs it on JDK 21. JDK 8 must stay the default for the ATL build
  (`archlinux-java status`; `sudo archlinux-java set java-8-openjdk` if a JDK install changed it).
  The package also puts `aapt` on `PATH`; ATL ignores it (see step 8).
- `smali` and `jasmin` only build the runtime tests (`tools/dine test runtime`).
- `swift-bin` installs into `/usr/lib/swift/usr` and only symlinks `swift`, `swiftc` and
  `sourcekit-lsp`, so it doesn't clash with system clang/lldb. **The Swift version must match
  the Xcode version** xtool expects (Swift 6.4 ↔ Xcode 27). Check xtool's docs when either one
  changes.
- `llvm` provides `llvm-ar` and `llvm-ranlib` for the iOS CMake toolchain. Arch's `clang`
  package doesn't include them. `lld` provides `ld64.lld` (Mach-O linker).
- `fuse2` runs the xtool AppImage (Arch ships only `fuse3` by default).
- `rustup`: run `rustup default stable` once; `ios run` builds accord (`../dine-accord`) with it.
- `bsd-compat-headers` is AUR-only, so pacman rejects it.
- **Do NOT install `usbmuxd`** (the daemon). It would fight the bridge for `/var/run/usbmuxd`.
  If something pulls it in, run `sudo systemctl mask usbmuxd.service`.
- `meson` and Python tooling are **not** from pacman; they come from the `.venv` (next step).

## 2. Python tooling (uv)

```sh
cd <repo>
uv sync              # .venv with CPython 3.12, pymobiledevice3, meson (versions from uv.lock)
source env.sh        # puts .venv/bin, out/tools/bin and tools/ on PATH (tools/dine sources it itself)
```

- `pyproject.toml` lists the tools in the `tools` dependency group (a default group, so plain
  `uv sync` installs it). Bump one with `uv lock --upgrade-package pymobiledevice3 && uv sync`.
- **Python is pinned to 3.12** on purpose: swift-bin's lldb links `libpython3.12`, which Arch
  doesn't ship, and `tools/libexec/lldb` (and the debug server) borrow it from this interpreter.
  pymobiledevice3 runs on the same one.
- No `uv run` needed: `env.sh` puts `.venv/bin` first on `PATH`.

## 3. Device bridge + tunnel (systemd)

```sh
sudo install -m644 tools/systemd/usbmuxd-bridge.service /etc/systemd/system/
sed "s|@DINE_ROOT@|$PWD|" tools/systemd/dine-tunneld.service | sudo tee /etc/systemd/system/dine-tunneld.service >/dev/null
(cd ../wsl-quickack && sudo make install)
sudo systemctl daemon-reload
sudo systemctl enable --now usbmuxd-bridge dine-tunneld wsl-quickack
idevice_id -l                                                        # prints UDID
ideviceinfo -q com.apple.security.mac.amfi -k DeveloperModeStatus    # prints true
tools/dine ios tunnel start            # waits for the tunnel, mounts the DDI (phone unlocked)
tools/dine ios tunnel status           # tunnel: up, quickack: on, ddi: mounted
```

- **usbmuxd-bridge** (socat) relays `/var/run/usbmuxd` to Windows' AMDS on `127.0.0.1:27015`.
  If `DeveloperModeStatus` prints `true`, the pairing record is being served correctly. On
  pairing errors, copy the Windows plist from step 0.2 into `/var/lib/lockdown/`. Replugging is
  handled by AMDS; nothing needs restarting on the WSL side.
- **dine-tunneld** runs `.venv/bin/pymobiledevice3 remote tunneld` as root (it creates a TUN
  interface) for iOS 17+ developer services. It needs `uv sync` done first; reinstall the unit if
  the repo moves. It sets `PYTHONDONTWRITEBYTECODE=1` so root never leaves files in `.venv`.
  Check it with `curl -s 127.0.0.1:49151`.
- **wsl-quickack** (`../wsl-quickack`, its README has the details) keeps `quickack 1` on the
  routes WSL's mirrored networking uses to reach Windows, through every rebuild WSL makes of
  them. Without it, AMDS's small writes wait for Linux's 40 ms delayed ACK, and every small lldb
  reply takes ~44 ms instead of ~1.6 ms.
- The Developer Disk Image is downloaded and personalized (signed by Apple) on first use. A phone
  reboot unmounts it: `tools/dine ios tunnel start` mounts it again.

## 4. xtool (manual download, in repo)

xtool isn't packaged for Arch, so it's the one binary downloaded by hand, pinned:

```sh
mkdir -p out/tools/bin
curl -fL https://github.com/xtool-org/xtool/releases/download/1.22.2/xtool-x86_64.AppImage \
  -o out/tools/bin/xtool && chmod +x out/tools/bin/xtool
xtool auth login                       # interactive
```

- **Login:** pick password mode for a free Apple ID, or API key mode for a paid developer
  account. Password mode uses private Apple APIs, so **use a throwaway Apple ID**. You'll get a
  2FA prompt.
- **Free account limits:** certificates expire after **7 days** (re-run `tools/dine ios run` to
  refresh), at most **3** sideloaded apps per device, and no paid-only entitlements. Bundle IDs
  get rewritten to `XTL-<TeamID>.<bundleID>`.
- **Always run xtool in a real terminal.** With stdin redirected from `/dev/null` it crashes with
  `epoll_ctl ... Operation not permitted`. For scripted use, wrap it with `script -qec "xtool …" /dev/null`.
- To update: download the new release over the old file (and check the Swift ↔ Xcode coupling).

## 5. iOS SDK from Xcode (manual download, in repo)

1. Download Xcode (the `.xip`) in a browser from
   <https://developer.apple.com/download/all/?q=Xcode>. It needs an Apple ID and accepting the
   license; `curl` won't work. Make sure the download is complete (a partial file fails late).
2. Copy it into the repo (reading from `/mnt/c` directly is slow), install, delete:
   ```sh
   mkdir -p out/downloads
   cp /mnt/c/Users/<you>/Downloads/Xcode_27.xip out/downloads/
   xtool sdk install out/downloads/Xcode_27.xip   # ~15 min
   swift sdk list                                 # → darwin
   rm out/downloads/Xcode_27.xip
   ```
   The SDK lands in `~/.swiftpm/swift-sdks/darwin.artifactbundle`; `env.sh` finds
   `iPhoneOS.sdk` there (`$DINE_IOS_SDK`) and the toolchain's Swift resource dir
   (`$DINE_IOS_SWIFT_RESOURCES`).

## 6. Debugger symbols (needs the phone)

```sh
tools/dine ios symbols      # phone's dyld shared cache → out/ios-symbols/<ver> (<build>)/Symbols
```

- Downloads the cache from the phone (7.2 GB, ~5 min), splits it with `ipsw` (6.7 GB), deletes
  the raw download. lldb then reads system library symbols from disk instead of device memory:
  Swift `po` needs them, system frames get names, and attach → first breakpoint takes ~4 s.
- Per iOS build: rerun after every iOS update (`ios lldb` and `dbg start-server` warn when they're
  missing).
- `tools/libexec/lldb` builds its relocated copy in `out/lldb/` on first use, no step needed. Why that and
  the rest exist: `notes/swift-dbg.md`.

## 7. First app install

Dine links ART and ATL and bundles their jars, so sections 8 and 9 come first, plus the authored
test jars its `art` screen runs: `tools/dine test runtime fetch`, then `tools/dine test runtime
build -f '^dine-'`.

```sh
tools/dine ios run                     # from a real terminal (prompts!)
```

1. **First run, certificate prompt:** a free Apple ID has only a few development-certificate
   slots, and xtool can't reuse one it didn't create. You may see
   `The following certificates must be revoked: … Continue? (yes/no)`. Answering `yes` invalidates
   certificates made by other sideload tools (AltStore, SideStore, Sideloadly) on that Apple ID,
   and apps they installed stop refreshing.
2. **Trust the developer:** the first launch fails with `Failed to launch process with bundle
   identifier …`. On the phone go to Settings → General → VPN & Device Management → your Apple ID
   → **Trust**, then rerun or launch again.
3. **Phone state:** keep it unlocked with the app in the foreground. A locked phone fails to
   launch with the *same* error as an untrusted certificate. A backgrounded app gets suspended and
   then killed. Set Settings → Display & Brightness → Auto-Lock → **Never** while developing.
4. `xtool dev` prints `DebugserverClient.Error.unknown` at the end. That's expected:
   xtool's own launcher doesn't work on iOS 17+. `ios run` ignores this one error and launches
   the app through pymobiledevice3 instead.

## 8. Linux ATL/ART stack

```sh
git submodule update --init dine-art dine-atl   # our ART and ATL forks (need GitHub SSH access)
mkdir -p third_party && cd third_party
for r in bionic_translation libopensles-standalone; do
  git clone https://gitlab.com/android_translation_layer/$r.git
done
git clone --depth 1 https://gitlab.com/android_translation_layer/atl_test_apks.git
cd .. && tools/dine linux build       # ~10 min on 16 cores; installs to out/linux/prefix (no sudo)
```

- `dine-art/` and `dine-atl/` are submodules: our forks of
  [art_standalone](https://gitlab.com/android_translation_layer/art_standalone) and
  [ATL](https://gitlab.com/android_translation_layer/android_translation_layer), both on branch
  `dine`, pinned by the superproject. Our ART/ATL changes live there. To follow upstream:
  `git -C dine-art remote add upstream https://gitlab.com/android_translation_layer/art_standalone.git`,
  `git -C dine-atl remote add upstream https://gitlab.com/android_translation_layer/android_translation_layer.git`.
- dine-atl dexes with `d8` (dine-art no longer installs `dx`) and only rebuilds
  `framework-res.apk` with `-Dregenerate_framework_res=true`. Upstream ATL regenerates whenever
  any `aapt` is on `PATH`, rewriting `src/api-impl/com/android/internal/{R,Manifest}.java` with
  different resource IDs, and android-sdk-build-tools puts one there.
- `third_party/` is gitignored; each clone is its own git repo.
- dine-art builds with **gcc** using art_standalone's own make-based build (not clang), in-tree
  (`dine-art/out`, ~2 GB, gitignored by the fork). Its makefile links
  `-ldl_bio` without pkg-config, so the script exports `LIBRARY_PATH` and `CPATH` for the local
  prefix.
- ATL's rpaths assume the bionic_translation libraries are in a system lib dir. `env.sh` adds
  `out/linux/prefix/lib` to `LD_LIBRARY_PATH` instead (checked: no names clash with `/usr/lib`).
- GUI apps open through WSLg (Wayland). No extra setup is needed.

## 9. ART and ATL for iOS

```sh
cd third_party
git clone --depth 1 --branch v1.10.0 https://github.com/lz4/lz4.git
git clone --depth 1 --branch v5.8.4 https://github.com/tukaani-project/xz.git
git clone --depth 1 --branch release-78.3 --filter=blob:none --sparse https://github.com/unicode-org/icu.git
git -C icu sparse-checkout set icu4c
git clone --depth 1 --branch v5.9.4-stable https://github.com/wolfSSL/wolfssl.git
cd .. && tools/dine ios build-art     # ICU, lz4, liblzma, wolfSSL, then dine-art → out/ios/lib/*.a
tools/dine ios build-atl              # dine-atl headless → out/ios/lib, its jars and demo_app.apk → out/ios/share/atl
```

- The versions match Arch's `icu`, `lz4` and `xz` and AUR's `wolfssl-jni`, so iOS and Linux use
  the same libraries. zlib and expat come from the iOS SDK. The SDK's own `unicode/` headers are a C-only ICU and are not
  used.
- dine-art builds for iOS with its make build in cross mode (`____TARGET=ios`, the
  `build/core/combo/HOST_darwin-arm64.mk` combo): clang, static archives, intermediates in
  `dine-art/out/host/darwin-x86`. The boot classpath jars come from the Linux build
  (`out/ios/share/art`, bundled as the app's `art/`).
- wolfSSL builds with autotools (`./autogen.sh` runs once in the clone; it needs autoconf,
  automake and libtool) and `--enable-jni`, as on Linux, plus system CA support. The app has no
  Java trust store, so wolfJSSE's default trust manager hands certificate checks to iOS (SecTrust:
  system roots and installed profiles). An app's own keystore never gets those roots.
- dine-art's iOS build includes androidfw, libutils and libcutils for ATL's resource natives,
  without aapt2's PNG code (the SDK has no libpng) and libutils' epoll `Looper`.
- dine-atl builds for iOS as a meson cross build (`-Dhost=embedded -Dloop=cfrunloop
  -Dui=headless -Dgfx=record`, build dir `out/ios/build/dine-atl`). It compiles no Java: the jars
  and the JNI headers in `src/api-impl-jni/generated_headers` come from the Linux build, so
  `tools/dine linux build atl` runs first.
- ICU's data is built into `libicudata.a` (`--with-data-packaging=static`, ~33 MB), as in Linux's
  system ICU; libcore never opens a data file.
- iOS links use xtool's `ld64.lld` (`DINE_IOS_TOOLSET_BIN` in `env.sh`): the system one rejects
  the SDK's `.tbd` stubs.

## 10. Verify

```sh
source env.sh
command -v pymobiledevice3 meson xtool               # all inside the repo (.venv, out/tools)
pymobiledevice3 usbmux list                          # phone visible
tools/dine ios run                                   # Dine shows the app grid
tools/dine ios logs                                  # "loaded N apps"; tap hello++ → "Dine native: Hello from C++ …";
                                                     # tap probe → "probe done N ok 0 fail" (accord's Assets.car)
                                                     # tap art → "art probe done"; run hello → ART's output
                                                     # fresh launch, tap atl → run demo → "- onResume - yay!"
tools/dine ios lldb -- -b -o "expr -l c -- (const char *)dine_hello()" -o "process detach"
tools/dine ios lldb --suspended -- -b -o "b HelloView.swift:8" -o c -o "po self" -o "process detach"
tools/dine test unit                                 # harness + tools unit tests (debug server on a fake target)
ANDROID_APP_DATA_DIR=$PWD/out/linux/appdata android-translation-layer \
  third_party/atl_test_apks/org.happysanta.gd_29.apk -l org/happysanta/gd/GDActivity -X -Xint
tools/dine test runtime                              # ART run-tests: exits 0 (no regressions)
tools/dine ios build-art                             # ART as arm64-apple-ios archives in out/ios/lib
tools/dine ios build-atl                             # ATL's headless build as an archive in out/ios/lib
```
