# Tests

Two worlds: the code that runs Android apps (`android-compat`), and Dine itself (`launcher`).
Each suite lives in the repo that owns the code it tests; the engine stays here.

| Suite | Lives in | Status |
|---|---|---|
| runtime: ART interpreter + libcore (AOSP ART run-tests) | `dine-art/tests/runtime/` | working (Linux) |
| headless: ATL's headless build runs demo_app (view-tree dump vs golden), the looper APK (loop paths, clean exit), the crash APK (an exception in `onCreate`, `onResume`, a posted Runnable or a started activity's `onCreate` ends ATL through the uncaught handler), the dialog APK (scripted answers, an alert that changes its buttons in onShow; also on gtk), the nav APK (Back, Home, front and insets through `-c`; the insets each show gets, exclusion spans, Back on a shown list), the views APK (frees, attach, widgets, keep screen on, fullscreen; also on gtk) and the widgets APK (taps, a hold, Tab and Enter, a scrolling drag and keys through `-c`, a press on one of two rows that share a selector resource, its controls activity: buttons, checkboxes, radios, a switch, a toggle and an image button, and `Html.fromHtml`'s bold as a text run, its lists activity: a ListView scrolled by 600 px, and its text activity: text fields through `-c` text lines, filters, watchers, a composition, a held report, focus moves and Back, and its draw activity: a Canvas view's display lists vs golden (clips, a PNG resource's bitmap, a filtered bitmap drawable and a tinted ImageView, a scrolled background, text, paths, arcs, a gradient, a layer, a nine-patch, a masked adaptive icon, a greyscale color matrix), a Canvas(Bitmap)'s pixel read back, an ImageView's bitmap redrawn 50 times, redrawn on invalidate and on showing again but not on a same-size layout, also drawn on gtk; on iOS also `dbg smoke atl-widgets` for checks by eye, `atl-controls`, `atl-text`, `atl-lists` and `atl-draw`, whose bar's redraws the display paces); `tools/dine linux smoke` runs them | `dine-atl/tests/headless/` | working (Linux) |
| framework: `android.*` APIs (ATL's api-impl), JUnit 3 in-VM on the headless build (`tools/dine test framework`), the gtk one (`--gtk`, on a hidden display) or as apps side by side in one headless VM (`--one-vm`); suites `basics` (also the ActionBar API, permissions, API level 29, activity lifecycle callbacks), `controls` (the Button family, AlertDialog's buttons), `graphics` (also bitmap pixels, VectorDrawable, shaders, XML drawables, color filters), `input` (touch dispatch, focus, keys, scroll, list scrolling without relayout), `text` (EditText's Editable, watchers, filters, the toolkit's reports, InputMethodManager, `Html` and spans) | `dine-atl/tests/framework/` | working (Linux headless, gtk) |
| package: install, query and removal through the registry on the headless build (`tools/dine test package`): CLI installs, uninstalls, path and `--package` runs graded on the registry's rows and files; a JUnit suite of `PackageManager` queries over installed fixtures (signatures, uids, `reqFeatures`, resolution across packages, the stored manifest's round trip, an extension's class loading); an installer app's sessions and intents, one process each with scripted dialog answers | `dine-atl/tests/package/` | working (Linux headless) |
| apps: real APKs to `onResume` and their log markers, no fatal line, still running after; an expected failure's reason names the app's stop and the stage that owns it, so a run is the ATL port's triage (`tools/dine test apps`, `--gtk`; `linux smoke gd` is its Gravity Defied on gtk; on iOS `dbg smoke atl-gd`) | `tests/android-compat/apps/` | working (Linux headless, gtk) |
| launcher: Dine's UI and logic | `tests/launcher/` | placeholder |
| probes: measurements behind a design, not graded; multi-app MA0: two apps in one host-ART VM, stopping one app's threads, dropping and reloading it (`tests/probes/multi-app/run.sh`, results in `out/probes/multi-app/results/`) | `tests/probes/` | Linux (host ART) |

`tests/harness/` is the engine (`tools/dine test runtime`, `tools/dine test framework`, `tools/dine test apps`). The corpus is mostly **harvested**
(AOSP ART run-tests, CTS, F-Droid apps), not written by hand; our own tests cover edge cases the
harvested ones miss.
